# «Словоград» — план разработки

## Контекст

Дочке-четверокласснице трудно с орфографией: мало читает, зрительный образ слов не накоплен, опасные места в словах не видит. ТЗ (`docs/SPEC.md`) описывает офлайн-PWA, которая превращает школьное задание в ежедневную игру на 10–15 минут: родитель фотографирует упражнение, Claude в claude.ai генерирует `lesson.json`, родитель проверяет и импортирует, ребёнок играет, коробки Лейтнера гоняют слова по интервалам.

Проект с нуля: `D:\Users\Maxim\_Repository\Slovograd` пуста, git не инициализирован. Окружение — Node v24.12, npm 11.6, git 2.53, Windows 11 + PowerShell.

Цель плана — довести до работающего вертикального среза, который дочка может открыть на телефоне, и сделать это так, чтобы первая её реакция пришла на первой-второй неделе, а не на третьем месяце.

## Правки к ТЗ, которые надо внести до кода

ТЗ сильное, но в девяти местах оно не доведено до состояния, из которого можно писать тесты. Критерии приёмки требуют юнит-тестов там, где правило описано словами.

### 1. Схема урока: добавить ударение и слоги

В `word` нет ударения — только `checkStressIndex` у проверочного слова. Ударение нужно для режима «как пишется» (§2), подсветки ударения (§11) и чтобы озвучка не врала.

```ts
word: {
  id, text, emoji?, context?,
  stressIndex: number,      // НОВОЕ, обязательное: индекс ударной гласной, с нуля
  syllables?: string[],     // НОВОЕ, необязательное: переопределение алгоритма
  orthograms: [...]
}
```

Слогоделение по умолчанию считается алгоритмом (`engine/syllables.ts`): для русского деление по гласным работает надёжно, поле в JSON — только для исключений.

### 2. Валидация в три уровня

Требование §4 «у проверочного слова совпадает корень» строго не проверяется — морфологии в браузере нет, полноценные словари весят мегабайты. Вместо этого:

**Жёсткие — блокируют импорт:**
- `schemaVersion === 1`; `type` входит в каталог из 18 кодов
- `index + length <= text.length`
- `text.slice(index, index + length) === correct` ← это и есть критерий приёмки «файл с неверной позицией буквы отклоняется»
- `distractors` непусты и не содержат `correct`
- `stressIndex` указывает на гласную; орфограммы одного слова не пересекаются по позициям; `word.id` уникальны
- для `ROOT_VOWEL_CHECK` с `method.kind === "check_word"`: `checkWord[checkStressIndex] === correct` — сильный проверяемый инвариант, ради которого правило и существует

**Мягкие — поднимают `needsReview`:**
- общий префикс `text` и `checkWord` короче 3 символов
- `confidence !== "high"`
- мнемоника не содержит ни целевую букву, ни само слово
- у слова больше 3 орфограмм; слово короче 3 букв

**Человеческие — только родитель:** смысл, правильность ударения, соответствие теме урока.

### 3. Звёзды: явный порядок приоритетов

Таблица §6 неоднозначна (складывается ли «+5 за проверочное» с «10 за первую попытку»? когда начисляется серия?), при этом на каждую строку нужен тест. Фиксируем: **одна попытка даёт ровно одно значение**, первое совпавшее правило выигрывает.

1. использованы подсказки → **5**
2. повтор после ошибки в той же сессии, верно → **3**
3. нажато «Сомневаюсь», затем окошко решено верно → **7**
4. игра «Проверялка», проверочное найдено верно с первой попытки → **15**
5. верно с первой попытки → **10**
6. ошибка → **0** (никогда не отнимаем)

Сверх того: завершение сессии **+30** (однократно, при ≥80% выполненных заданий); серия **`min(10 × день_серии, 70)`** — один раз в день, при первой завершённой сессии; победа в Битве с Кляксой **+100**.

### 4. «Задание» — определить единицу

Элемент повторения = пара «слово + орфограмма» (§10, хранилище `items`). Слово с двумя орфограммами — два элемента. Урок из 12 слов даёт 15–18 элементов. Единица сессии — **встреча** = (элемент, игра).

- `targetEncounters = round(durationMin × 1.8)` → 10 мин ≈ 18, 15 мин ≈ 27
- новый элемент (коробка 0) получает **3 встречи** за сессию в разных играх; элемент в коробке ≥1 — **1 встречу**
- слабый тип орфограммы (<70% за последние 20 попыток) — **+1 встречу**
- до 40% встреч — просроченные повторения, самые старые первыми
- сборка детерминирована по seed → тестируема

### 5. Адаптивность не должна ломать коробки

«3 ошибки подряд → уровень легче» конфликтует с тем, что тип задания задаёт коробка. Разводим:

- `sessionDifficultyOffset ∈ {−1, 0, +1}`, стартует с 0, живёт только внутри сессии
- 3 ошибки подряд → −1 и ободряющая пауза с Кляксой; 5 верных подряд → +1
- отображаемая сложность = `clamp(box + offset, 0, 5)` — влияет **только на выбор игры и числа вариантов**
- переход по коробкам считается по факту (верно / с подсказкой / ошибка), как в §7, и offset его не трогает

### 6. Сжатие под диктант — формула

```
days = dictationDate − today
days >= 7        → обычные интервалы
days 4..6        → 3 повторения: сегодня, сегодня + floor((days−1)/2), накануне
days 2..3        → 2 повторения: сегодня, накануне
days <= 1        → 2 встречи сегодня с разрывом не меньше 3 заданий
```

### 7. Своя клавиатура, не системная

Системная клавиатура даст автозамену, Т9 и подсказки слов — на диктанте это фатально. Нужна своя кириллическая раскладка: `ё` отдельной клавишей, клавиши ≥48 px на телефоне, никакой автокоррекции, кнопка «Сомневаюсь» рядом с пробелом.

### 8. Озвучка — один интерфейс, два режима

```ts
speak(text: string, mode: "natural" | "spelling"): Promise<void>
```

Реализация за интерфейсом, игры про неё не знают. По итогам задачи 0.1 источники разведены жёстко:

| Режим | Источник |
| --- | --- |
| Инструкции, `natural` | `speechSynthesis` — редукция здесь правильна |
| `spelling` | **только запись из IndexedDB** |

`spelling` никогда не падает обратно на синтез: движок произнесёт «КАрова» и тем самым
закрепит ровно ту ошибку, которую урок исправляет. Нет записи — игра честно предлагает
послушать у папы и не произносит эталон вслух.

### 9. Версии стека изменились с момента написания ТЗ

Zod 4 умеет `z.toJSONSchema()` нативно — пакет `zod-to-json-schema` не нужен. Tailwind 4 — конфиг в CSS, не в `tailwind.config.js`. TypeScript 7.0 — нативный компилятор. Vite 8, React 19, Vitest 5, Phaser 4 (в ТЗ указан 3).

## Этап 1 — вертикальный срез (39 сессий)

Каждая задача рассчитана на одну 20-минутную сессию и имеет проверяемый результат. Порядок внутри блока важен, блоки A–D идут строго последовательно.

### Порядок: сначала петля возвращения, потом остальные игры

Правка после задачи 0.4 (2026-09-24). Дочке игра понравилась, но **сама играть она
не просит** — а по §1 ТЗ это и есть метрика интереса. В прототипе нечему было тянуть
обратно: звёзды исчезали при перезапуске, призов нет, серии нет, слова одни и те же.

Поэтому блоки идут не подряд. Сначала собирается **первая живая сессия** — самый
короткий путь до состояния, когда возвращаться назавтра есть зачем:

> A1–A4 · B1–B5 · C1, C2, C6 · D1–D3 · E1 · F1 · **F5 («Кто самозванец?» — перенос
> готовой игры)** · G1, G2 · **G4 (призы)** · **H2 (звёзды, уровень, серия на экране)**

После этого — проверка на дочке: **просит ли сама**. Если да, доделываем остальное
(C3–C5, D4, E2–E5, F2–F4, F6, G3, G5, H1, H3, H4). Если нет — проблема в самой игре,
и это надо решать до того, как строить ещё три.

Смысл в том, чтобы не узнать на тридцатой сессии то, что можно узнать на
пятнадцатой. Общий объём задач не меняется, меняется только порядок.

| E2 | «Голос папы»: запись слов в кабинете через MediaRecorder, хранение Blob в IndexedDB, перезапись и прослушивание | Родитель записывает 12 слов урока меньше чем за 3 минуты |
| E3 | Режим «как пишем» на записях + деградация: если записи нет, игра честно говорит «послушай у папы», а не проговаривает «КАрова» | Ни один экран не произносит редуцированную гласную как эталон написания |
| E4 | Своя кириллическая клавиатура под 360 px, с `ё` и кнопкой «Сомневаюсь» | Ввод слова без автозамены; клавиши не меньше 48 px |
| E5 | Howler: звуки верно/ошибка/награда, реакции Кляксы | Звук не перекрывает озвучку, глушится на паузе |

**Почему так.** Задача 0.1 показала: движок применяет редукцию безусловно, и все
пять обходов (слоги отдельными фразами, медленно, через точки, знак ударения
U+0301, по буквам) дают «А» вместо «О». Но редукция — правильное поведение для
инструкций, режима «как говорим» и аудиодиктанта: ребёнок и должен слышать
«КАрова», а писать «корова», в этом контрасте весь смысл двух режимов.
Записывать нужно только режим «как пишем» — 8–15 слов на урок.

## Проверка

**На каждой задаче:** `npm run lint; npm test` — зафиксировано в `CLAUDE.md` как условие завершения.

**Движок (блоки B, C):** только Vitest, без интерфейса. Тесты пишутся до кода — это самая дешёвая часть проекта и самая дорогая в отладке потом.

**Игры и кабинет (F, G):** Playwright по сценариям + ручная проверка на телефоне после каждой игры.

**Сквозная проверка перед закрытием этапа 1:**

```bash
npm run schema; npm run lint; npm test; npm run test:e2e; npm run build
```

Затем вручную на телефоне: развернуть на GitHub Pages → открыть → установить на экран → включить авиарежим → импортировать урок из задачи 0.3 → пройти сессию целиком → проверить начисленные звёзды → выгрузить бэкап → очистить данные → восстановить из бэкапа.

**Главная проверка — не техническая.** После каждой готовой игры дочка играет в неё в тот же вечер. Если игра не зашла, дешевле переделать её сразу, чем обнаружить это на 37-й сессии.

## Календарь

43 сессии × 20 минут при 3–4 сессиях в неделю:

- **Недели 1–2**: этап 0 — дочка уже играет во что-то реальное
- **Недели 3–5**: блоки A, B — фундамент и схема
- **Недели 6–8**: блоки C, D — движок и хранилище, всё под тестами
- **Недели 9–11**: блоки E, F — озвучка и три игры, каждая проверяется в тот же вечер
- **Недели 12–13**: блоки G, H — кабинет, сборка, приёмка

Итого ~3 месяца до готового среза. Заявленные в ТЗ 6–10 вечеров относятся к куда меньшему объёму, чем перечислено в §12.
